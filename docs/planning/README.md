# ESG 데이터 입력플랫폼 기획 (스토리텔링 기반)

> 파워넷㈜ 경영지원실 · 최초 작성 2026-09-17

## 이 문서 묶음의 목적

ESG 데이터 입력플랫폼의 기획을 **스토리텔링 방법론**으로 진행한 기록이다.
각 에피소드는 "장면"으로 시작해 **그 장면이 성립하기 위한 요구사항**으로 끝난다.
따라서 이 문서는 두 가지로 동시에 쓰인다.

1. 개발 단계의 요구사항 명세서 (EP1~5가 기능 요구사항의 출처)
2. 대표이사·노사협의회 설득용 내러티브 (EP1→2→4→8 순서로 발췌하면 보고서가 된다)

## 확정된 전제 (2026-09-17)

| 항목 | 결정 |
|---|---|
| **프로젝트 취지** | **선제적 ESG 대응** — 규제 대응이 아니다 |
| **최종 목표** | **2027년 지속가능경영보고서 자체 발간** (외주 컨설팅 없이) |
| 적용 범위 | **3법인 동시 통합** — 서울 본사 / 중국 심양 / 베트남 빈푹 |
| 1차 목적 | ① 온실가스·에너지 데이터 관리 ② 지속가능경영보고서 ③ 내부 ESG KPI·경영관리 |
| 입력 주체 | **10명 내외.** 법인별 업무담당자 지정. 해외법인은 담당자 1인이 전 항목 |
| 구축 방향 | **자체 웹앱** — Cloudflare + Claude API |
| 사내 전산팀 | 없음 (경영지원실 파트장 + AI 도구 의존) |
| 보고 프레임워크 | **GRI Standards 주축 + KSSB·IFRS S1·S2 병기** |
| 1차 지표 범위 | **E 전체 + S 핵심** (G는 2차) |
| 소급 입력 범위 | **2025 ~ 2026 (2개년)** + 증빙 확보 항목만 2024 선택 추가 |
| 제3자 검증 | 첫 회 미검증. 단 구조는 검증 대응 가능 수준 |
| 1차 오픈 목표 | **2026년 12월** |

> **보류 사항**: 노사협의회 관련 협의 절차는 추후 논의. 고객사 공급망 실사(삼성·RBA)
> 대응은 1차 목적에서 제외되었으나 **실질적 데드라인의 주된 출처**이므로(EP2 4절),
> 데이터 모델은 실사·PCF 대응이 가능한 구조로 설계한다.

## 설계 원칙 (EP3 도출 — 전 설계의 상위 규범)

| # | 원칙 |
|---|---|
| **P-1** | 입력자는 숫자만 안다 — 환산·배분·계수·환율은 전부 시스템이 |
| **P-2** | "모름"이 허용돼야 데이터가 정직해진다 |
| **P-3** | 동기 없는 사람에게는 3분 이하 |
| **P-4** | 독려는 시스템이, 사람이 하지 않는다 |
| **P-5** | 현지 관행을 본사 기준으로 교정하지 않는다 |
| **P-6** | 본사는 "내 항목만", 해외법인은 "한 화면에 전부" |
| **P-7** | 1인 의존을 허용하지 않는다 — 부담당자 필수 |

## 누적 요구사항

**R1 ~ R69 (65건).** 전 요구사항이 장면 또는 규제 근거에 연결되어 있다.

## 검토 방식

EP1~3의 등장인물과 장면은 **실제 파워넷 상황을 가정한 초안**이다.
현실과 다른 부분은 해당 문서에 직접 수정 표시하거나 코멘트로 지적하면
EP4 이후 설계에 반영한다. 특히 다음 항목은 사실 확인이 필요하다.

- [ ] EP1의 데이터 수집 경로가 실제와 일치하는가
- [ ] EP1의 공수 추정(요청 1건당 84시간)이 과대/과소한가
- [ ] EP2의 빈푹 공장 Decision 13/2024 목록 등재 여부 — **최우선 확인 과제**
- [ ] EP3의 페르소나 7종에 누락된 입력 주체가 있는가
