## 2. 🔴 자체수행을 성립시키는 6가지 원칙

> 이 6가지가 지켜지면 비개발자도 AI와 함께 4주에 만들 수 있다.
> 하나라도 깨지면 중간에 멈춘다. **기술적 취향이 아니라 성공 조건이다.**

### 원칙 1. 파일을 10개 이하로 유지한다

AI는 **전체 코드를 한 번에 볼 수 있을 때** 수정이 정확하다. 파일이 50개로 흩어지면
AI가 맥락을 잃고, "여기를 고쳤는데 저기가 깨지는" 상황이 반복된다. 비개발자는 이 상황을 복구할 수 없다.

```
esg-platform/
├── wrangler.toml          배포 설정            (20줄)
├── schema.sql             DB 테이블 정의       (200줄)
├── seed.sql               마스터 초기 데이터   (150줄)
├── src/api.js             API 전체 (Worker)    (600줄)
├── src/calc.js            산정 로직            (150줄)
├── public/index.html      전체 화면            (400줄)
├── public/app.js          화면 로직            (600줄)
└── public/app.css         스타일               (300줄)
```

**8개 파일, 약 2,400줄.** 이 규모면 AI가 전체를 파악한 채 작업할 수 있다.

### 원칙 2. 빌드 단계를 만들지 않는다

| 만들지 않을 것 | 이유 |
|---|---|
| npm 패키지 다수 설치 | 버전 충돌 시 비개발자가 해결 불가 |
| 트랜스파일·번들러 | 빌드 실패 원인 추적 불가 |
| 프론트엔드 프레임워크 | 학습·유지보수 부담. 화면 11개에 불필요 |

**설치하는 것은 `wrangler` 하나. 배포는 `npx wrangler deploy` 한 줄.**
브라우저가 그대로 읽는 HTML·JS·CSS만 쓴다. 파일을 고치면 배포하면 끝이다.

### 원칙 3. 하루 1기능, 끝나면 즉시 배포·확인

> **가장 중요한 원칙이다.**

한 번에 전체를 만들면, 안 될 때 **어디서 틀렸는지 알 수 없다.**
개발자는 디버깅으로 찾지만, 비개발자에게는 찾을 방법이 없다.

```
❌ 금지: "입력 화면 전체 만들어줘" → 안 됨 → 원인 불명 → 막힘
✅ 권고: "항목 목록만 화면에 뿌려줘" → 배포 → 확인 → OK
        "입력칸 추가해줘" → 배포 → 확인 → OK
        "저장 버튼 붙여줘" → 배포 → 확인 → OK
```

각 단계가 30분~2시간이고, **직전 단계가 동작함을 알기 때문에 문제 범위가 항상 좁다.**

### 원칙 4. 스키마를 먼저 완전히 확정하고, 이후 바꾸지 않는다

스키마(DB 테이블 구조)가 흔들리면 **이미 만든 화면을 전부 다시 만들어야 한다.**
W1에 스키마를 확정하고, 이후 3주간 변경하지 않는다.

→ 그래서 **EP5의 데이터 모델을 그대로 쓴다.** 이미 설계가 끝나 있는 것이 자체수행의 최대 자산이다.

### 원칙 5. 화면은 "가짜 데이터부터" 넣고 확인한다

빈 화면을 예쁘게 만들지 말고, 가짜 데이터라도 채워서 **눈으로 확인**한다.
데이터가 보이지 않는 화면은 맞는지 틀린지 판단할 수 없다.

### 원칙 6. 오류가 나면 AI에게 오류 메시지 전문을 붙여넣는다

요약하지 않는다. "저장이 안 돼요"가 아니라 **브라우저 콘솔과 wrangler 로그를 그대로** 붙여넣는다.
AI는 오류 메시지 한 줄로 원인을 특정할 수 있지만, 요약된 증상으로는 추측만 한다.

## 4. 🔴 개인정보 Zero 설계 — 조심하는 것이 아니라 불가능하게 만든다

> 종전 설계(P-8)는 "개인 단위 데이터를 올리지 않는다"는 **운영 원칙**이었다.
> 이제 **구조적으로 올릴 수 없게** 바꾼다. 원칙은 지켜지지 않을 수 있지만, 구조는 지켜진다.

### 4-1. 4단 방어

| 단계 | 조치 | 효과 |
|---|---|---|
| **1. 스키마** | **개인 식별 컬럼이 존재하지 않는다.** 이름·사번·연락처·주민번호·여권번호 컬럼을 만들지 않는다 | 넣으려 해도 **넣을 곳이 없다** |
| **2. 사용자 기록** | 사용자를 **이메일·이름이 아닌 역할코드**로 기록 — `HQ_FACILITY`, `HQ_HR`, `SY_OWNER`, `VP_OWNER` | 입력 이력이 "누가"가 아니라 **"어느 법인의 어느 역할"** 로 남는다 |
| **3. 증빙 첨부** | **S(사회) 지표에는 첨부 버튼이 존재하지 않는다** | 급여대장·근태표·재해조사표를 **올릴 방법이 없다** |
| **4. 자유 텍스트** | **자유 입력칸을 만들지 않는다.** 미확보 사유도 선택형(드롭다운)만 | 자유칸이 있으면 누군가 이름을 적는다. 칸이 없으면 적을 수 없다 |

### 4-2. 2단계가 핵심 — 사람을 기록하지 않고 역할을 기록한다

```
❌ 종전:  entry.entered_by = "wang@powernet.cn"
✅ 변경:  entry.entered_by = "SY_OWNER"

이메일 ↔ 역할 매핑은 Cloudflare Access(인증 계층)에만 존재한다.
우리 DB에는 어떤 개인정보도 저장되지 않는다.
```

| 효과 | 내용 |
|---|---|
| 규제 | 중국 PIPL·베트남 Law 91/2025의 **개인정보 국외이전 규제 적용 대상 자체가 되지 않는다** |
| 승계 | 담당자가 교체되어도 **역할코드가 그대로 이어진다.** 계정 이관 절차가 단순해진다 (R31) |
| 감사 | 10명 규모에서 역할과 사람이 1:1이므로 **실무상 추적성 손실이 없다** |

### 4-3. S 지표 입력 형태 — 전부 숫자 또는 선택형

| 지표 | 입력 형태 |
|---|---|
| 인원 현황 | 고용형태별·성별 **인원 수(숫자)** |
| 신규채용·퇴사 | **인원 수(숫자)**. 자발/비자발 구분도 각각 숫자 |
| 산업재해 | **건수(숫자)** + 재해유형 **선택형 코드**. 재해자·상병명 입력칸 없음 |
| 근로손실일수 | **일수(숫자)** |
| 교육시간·근로시간 | **시간(숫자)** |
| 관리직·육아휴직 | **인원 수(숫자)** |

> **S 지표 화면에는 텍스트 입력칸이 단 하나도 없다.** 숫자칸과 드롭다운만 존재한다.

### 4-4. 미확보 사유 — "기타(자유입력)"을 제거한다

종전 R25는 사유에 "기타(자유입력)"을 포함했다. **자유입력을 제거한다.**

```
✅ 고지서 미도착    ✅ 해당 없음
✅ 담당부서 미회신  ✅ 증빙 보관기간 경과
✅ 시스템 미집계    ❌ 기타(자유입력) ← 제거
```

6개 선택지로 실무 사유는 모두 커버된다. 부족하면 **선택지를 추가**하고, 자유칸은 만들지 않는다.

## 6. AI에게 주는 지시문 패턴

> 좋은 지시문이 개발 속도를 결정한다. 아래 패턴을 그대로 쓴다.

### 패턴 1. 화면 만들기

```
schema.sql의 entry / metric 테이블을 사용해서 public/ 에 월간 입력 시트를 만들어줘.

[사용자]   해외법인 담당자 1명이 한 화면에서 전 항목을 입력한다
[화면구성] 상단: 대상월 · 진행률(18/24) · 마감 D-day · 언어전환(한/중/베)
          본문: 항목 행 리스트
                열 = 항목명(현지어) | 단위(고정 표시) | 전월값(회색) | 입력칸 | 상태
          하단: 임시저장 / 제출
[동작]     - 미확보 토글 → 선택형 사유 6개 중 선택 (자유입력 없음)
          - 전월 대비 ±30% 초과 시 경고 표시 (저장은 막지 않음)
          - 단위는 법인별 고정값을 표시만 한다 (담당자가 환산하지 않음)
[제약]     프레임워크 없이 vanilla JS. 파일은 public/app.js 에 추가.
          외부 라이브러리 추가하지 말 것.
```

### 패턴 2. 오류 해결

```
S1 화면에서 저장 버튼을 눌렀는데 저장이 안 돼.

[브라우저 콘솔]
POST https://esg.powernet.co.kr/api/entry 500 (Internal Server Error)
Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'id')
    at app.js:214

[wrangler tail 로그]
✘ [ERROR] D1_ERROR: NOT NULL constraint failed: entry.metric_code

원인 찾아서 고쳐줘.
```

> 요약하지 않고 **전문을 붙여넣는 것**이 핵심이다.

### 패턴 3. 기능 추가 (기존 코드 유지)

```
S1 화면에 진행률 표시를 추가해줘.
- 위치: 상단 헤더 우측
- 내용: "24개 중 18개 완료" + 진행바
- 기존 코드는 건드리지 말고 추가만 할 것
- 수정한 파일과 줄 번호를 알려줘
```
