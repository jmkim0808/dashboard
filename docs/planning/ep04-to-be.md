# EP4. 바뀐 3월 — to-be 장면과 화면

> 목적: **미래의 장면을 먼저 쓰고, 그 장면이 성립하려면 어떤 화면이 필요한지** 역으로 도출한다.
> 기능 목록에서 시작하면 "있으면 좋은 기능"이 쌓인다. 장면에서 시작하면 **없으면 장면이 깨지는 기능**만 남는다.
>
> 전제: EP3의 설계원칙 **P-1 ~ P-7** 에 종속된다.

## 장면 A — 2027년 3월 4일 오전 9시 14분

EP1과 같은 날, 같은 시간, 같은 메일이 도착한다.

> 2026년 기준 **사업장별** 온실가스 배출량(Scope 1·2) 및
> 당사 공급 품목의 **제품 탄소발자국(PCF)** 데이터를 별첨 양식으로 **3주 내** 제출 요청.

P1(ESG 총괄)이 하는 일:

**09:15** 플랫폼에 접속한다. 조회 화면에서 기간 `2026-01 ~ 2026-12`, 법인 `전체`를 선택한다.
Scope 1·2 배출량이 사업장별로 표시된다. 옆에 적용 계수와 버전이 함께 표시된다.

**09:22** 제품별 배분 탭으로 이동한다. 2026년 생산량 기준으로 배분된 제품 단위 배출량이 이미 계산되어 있다.
고객사 품번으로 조회한다. 매칭 테이블이 시스템에 있으므로 영업팀에 물어볼 일이 없다.

**09:40** 대외 산출물 생성에서 해당 고객사 양식을 선택한다. 값이 자동으로 채워진다.
**두 칸이 비어 있다.** "폐기물 재활용률 – 2026년 3월: 미확보(위탁업체 전표 미수령)".
빈칸은 숨겨지지 않는다. P1은 그 한 건만 처리하면 된다.

**10:05** 파트장(P9)에게 승인 요청. 파트장은 값을 클릭해 **증빙 원본까지 3단계로 역추적**하고 승인한다.

**10:30** 제출. 제출 이력이 기록된다. *"2027-03-04, ○○고객사, 2026년 Scope1·2, 계수버전 v2026.1"*

> **6월에 다른 고객사가 같은 질문을 하면, 시스템은 같은 답을 낸다.**
> 이것이 EP1 결손 1(재현 불가능성)의 해소다.

## 장면 B — 2027년 4월, 보고서 킥오프 회의

대표이사와 파트장, P1이 2027년 지속가능경영보고서 킥오프 회의를 한다.
외주 컨설팅 없이, 우리 손으로 낸다는 결정이 서 있다.

P1이 화면 하나를 띄운다. **지표 데이터북**이다.

| 지표 | 단위 | 2024 | 2025 | 2026 | GRI | KSSB |
|---|---|---|---|---|---|---|
| Scope 1 배출량 | tCO2eq | – | 확보 | 확보 | 305-1 | S2 |
| Scope 2 배출량 (location) | tCO2eq | 확보 | 확보 | 확보 | 305-2 | S2 |
| 에너지 사용량 | TJ | 확보 | 확보 | 확보 | 302-1 | S2 |
| 용수 취수량 | ton | – | 확보 | 확보 | 303-3 | – |
| 폐기물 배출량 | ton | – | 확보 | 확보 | 306-3 | – |
| 재해율 | % | 확보 | 확보 | 확보 | 403-9 | – |
| 이직률 | % | 확보 | 확보 | 확보 | 401-1 | – |

대표이사가 묻는다. **"2024년에 빈 게 몇 개인가."**
P1이 답한다. **"5개입니다. 증빙이 없어서 비워뒀습니다. 추정치를 넣지 않았습니다."**

회의의 성격이 바뀐다. "데이터를 모으자"가 아니라 **"이 5개를 어떻게 다룰지"** 를 논의한다.
보고서에 2개년 추이로 실을 것인지, 해당 지표만 주석을 달 것인지.

> **이것이 선제 대응형 프로젝트의 성과다.** 성과는 숫자가 아니라 **의사결정 가능한 상태**다.
> (EP2 0절 근거 5 — 선제 대응의 첫 성과는 가시성)

## 장면 C — 매월 5일, 두 사람의 시간

### 본사 총무·시설 담당(P2) — 3분

점심시간, 스마트폰에 알림이 온다. *"2027년 4월분 입력 3건이 남았습니다."*

카드 세 장이 뜬다. 첫 장은 `본사 전력 사용량`.
- 입력칸 하나. 단위 `kWh`는 이미 고정되어 표시된다.
- 아래 회색으로 *"전월 18,420 kWh"*.
- 사진 첨부 버튼 하나.

고지서를 사진으로 찍어 올리고, 숫자를 입력한다. `19,100`. 다음 카드로 넘어간다.
세 장을 끝내는 데 3분이 걸린다. **P2는 배출계수를 본 적이 없다.** 볼 필요도 없다. (P-1)

### 심양법인 담당자(P7) — 22분

출근해서 플랫폼을 연다. 화면 상단에 중국어로 *"2027년 4월 입력 · 0/24 완료 · 마감 D-5"*.

**한 화면에 24개 항목이 세로로 나열되어 있다.** 클릭해 들어갈 필요가 없다. (P-6)

| 항목 (中文) | 단위 | 전월 | 입력 | 증빙 | 상태 |
|---|---|---|---|---|---|
| 用电量 | **万kWh** | 124.0 | `126.5` | 📎 | ✅ |
| 自来水 | ton | 840 | `865` | 📎 | ✅ |
| 一般废弃物 | ton | 12.4 | — | — | ⏸ **未获取** |

전기 사용량 칸의 단위는 `万kWh`다. P7이 환산하지 않는다. 시스템이 한다. (P-5)

세 번째 항목에서 P7은 **"未获取(미확보)"** 를 누르고 사유를 선택한다. *"위탁업체 전표 미수령"*.
화면에 안내가 뜬다. **"미확보는 정상적인 입력 상태입니다. 확보되면 나중에 입력하실 수 있습니다."** (P-2)

15번째 항목에서 실수로 `1265`를 입력한다. 즉시 경고가 뜬다.
*"전월 대비 +920%입니다. 단위를 확인해 주세요. (万kWh)"* P7이 `126.5`로 고친다. (R24)

22분 뒤 제출. **"未获取 2건, 입력완료 22건"** 으로 제출된다.
빈칸을 메우기 위해 야근하지 않았고, 추정치를 만들지 않았다.

> **EP1의 "만kWh 사건"과 "추정치 12칸"이 구조적으로 발생할 수 없게 되었다.**

## 화면별 설계 요건

### S1. 월간 입력 시트 — 해외법인 전용

> **이 화면 하나가 프로젝트의 성패를 가른다.** P7·P8이 월 24개 항목을 여기서 끝낸다.

| 영역 | 요소 |
|---|---|
| 상단 | 대상 월 · 진행률(18/24) · 마감 D-day · 언어 전환 |
| 본문 | 항목 행 리스트. 열 = 항목명(현지어) / **단위(고정 표시)** / 전월값(회색) / 입력칸 / 증빙첨부 / 상태 |
| 상태값 | `미입력` `입력완료` `미확보(사유)` `반송(사유)` |
| 미확보 처리 | 토글 + 사유 선택(고지서 미도착 / 해당 없음 / 담당부서 미회신 / 기타) + **"미확보는 정상 상태" 안내 문구** |
| 검증 | 전월 대비 ±30% 초과 시 **입력 즉시 경고** (차단 아님, 경고) |
| 하단 | 임시저장 / 제출 |
| 항목 도움말 | 각 항목에 "이 숫자는 어디서 찾나" 안내 내장 (R53) |

관련 요구사항: R22~R30, R50, R52, R53, P-2, P-5, P-6

### S2. 항목 입력 카드 — 본사 담당자, 모바일 우선

| 영역 | 요소 |
|---|---|
| 목록 | **내 담당 항목만** 카드로. 남은 건수 표시 |
| 카드 1장 | 항목명 / 단위(고정) / 입력칸 **3개 이하** / 전월값 / 사진 첨부 1개 / 다음 |
| 목표 | 카드 1장 30초, 전체 **3분 이내** (P-3) |
| 진입 | 알림(카카오톡/메일) 링크 클릭 → 로그인 → 바로 카드 |

> 설계 금지 사항: PC 화면을 반응형으로 줄여 모바일에 쓰는 것. **P2는 현장에 있다.** (R21)

관련 요구사항: R21~R24, P-1, P-3

### S3. 파일 업로드 입력

| 대상 | 원천 | 처리 |
|---|---|---|
| 생산량·모델코드 (P5) | ERP 추출 엑셀 | 자동 파싱 → **모델코드↔고객사품번 자동 매칭** |
| 인사 지표 (P3) | 급여·근태 시스템 추출 | 자동 파싱 → 산정정의 적용 |
| 구매 자재 (P6) | 구매 시스템 추출 | 자동 파싱 |

- 업로드 후 **매핑 실패 행만** 화면에 표시. 성공 행은 보여주지 않는다. (P5의 5분 목표)
- 동일 기간 재업로드 시 **덮어쓰기 여부와 변경 이력**을 남긴다.

관련 요구사항: R18, R19, R20, R48

### S4. 입력 현황 보드 — P1의 첫 화면

> **첫 화면은 숫자가 아니라 빈칸 목록이다.** (R15)

| 영역 | 요소 |
|---|---|
| 기본 뷰 | **법인 × 항목 × 월 매트릭스.** 5색 — 미입력 / 미확보 / 입력완료 / 이상치 / 승인완료 |
| 정렬 | 미입력·이상치가 상단 |
| 액션 | 미입력 셀 클릭 → **담당자에게 알림 발송** (P1이 전화하지 않는다, P-4) |
| 자동 알림 | 매월 1일 시트 생성 알림 / 5일 1차 리마인드 / 8일 2차 / 마감 후 미입력 시 파트장 통보 |
| 10명 규모 반영 | **개인 알림 중심.** 전체 공개 랭킹·비교 화면은 만들지 않는다 (EP3 0절) |

관련 요구사항: R15, R16, P-4

### S8. 대외 산출물 생성 · 제출 이력

| 영역 | 요소 |
|---|---|
| 템플릿 | 고객사 양식별 템플릿 → 자동 채움 |
| 공개등급 필터 | **자동 적용.** 사람 판단에 맡기지 않는다 (R40) |
| 미확보 표기 | 숨기지 않고 `미확보(사유)`로 표시 (P-2) |
| 승인 | **P9 최종 승인 없이 다운로드 불가** (R54) |
| 제출 이력 | 일자 / 수신처 / 대상기간 / 제출값 / **적용 계수버전** 기록 (EP1 결손 1 직접 대응) |

> ⚠️ **1차 범위 제한**: 고객사 양식 템플릿 자동화는 **양식이 수집된 뒤**에만 가능하다.
> 1차에서는 **제출 이력 기록 + 표준 엑셀 인출**까지 구현하고, 템플릿 자동화는 2차로 분리한다.

관련 요구사항: R40, R54, R2

| 법인·사업장 | 3법인 + 사업장 단위. 임대 사업장은 **배분 기준(면적 등)과 근거 기록** (EP1 3월 5일) |
| 항목 | 항목명(한/중/베) · 단위 · 산정정의 · 공개등급 · 담당자 · **부담당자(필수)** · 프레임워크 매핑 |
| 배출계수 | **연도별 · 지역별 버전 관리.** 한국 / 중국 동북전망 / 베트남. 출처·고시일 기록 |
| 환율 | 기준일별 환율. 적용 이력 기록 |
| 산정표준 | 법인별 적용 표준 명시 — 한국 온실가스 산정지침 / 중국 GB/T 32150-2025 / 베트남 Decree 06/2022 (R11) |
| 소급 가능 연도 | **항목별·법인별 "확보 가능한 최초 연도"** (R43) |
| 계수 변경 | 변경 시 **소급 재계산 여부를 선택**하고, 기존 산출물의 계수버전은 보존 |

관련 요구사항: R3, R11, R14, R39, R43, R51

### S11. 증빙 보관함

| 영역 | 요소 |
