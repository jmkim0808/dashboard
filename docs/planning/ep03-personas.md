# EP3. 사람들 — "데이터를 만드는 손"

> 목적: 30명 이상의 입력자를 **유형화**하고, 각자의 **동기와 저항**에서 권한·UI 요구사항을 도출한다.
> 이 에피소드의 전제: **ESG 데이터 입력은 누구의 KPI도 아니다.**
> 따라서 "잘 협조해줄 것"이라는 가정 위에 설계하면 3개월 안에 빈칸 플랫폼이 된다.

## P1. 박 주임 — 본사 경영지원실, ESG 데이터 총괄

| 항목 | 내용 |
|---|---|
| **역할** | 전 법인 데이터 검증·승인, 배출량 산정, 대외 제출자료 작성 |
| **동기** | ★★★★★ — EP1의 3월을 다시 겪고 싶지 않다 |
| **저항** | 없음. 단 **"시스템이 또 하나의 일이 될 것"** 을 두려워한다 |
| **가장 두려운 것** | 입력자들이 안 넣어서, 결국 자기가 다 넣게 되는 상황 |
| **현실 제약** | ESG는 박 주임 업무의 일부다. 인사·노무·총무 업무가 병행된다 |

### 도출 요구사항
- **R15** 대시보드 첫 화면은 "**누가 무엇을 아직 안 넣었는지**"다. 숫자가 아니라 **빈칸 목록**이 먼저다.
- **R16** 마감 독려는 **시스템이 자동 발송**한다. 박 주임이 사람에게 전화하게 만들면 실패한 설계다.
- **R17** 승인은 **일괄 처리** 가능해야 한다. 30명 × 12개월 × 항목수를 건별로 누를 수 없다.

## P2. 김 과장 — 본사 생산관리

| 항목 | 내용 |
|---|---|
| **역할** | 제품별 생산량, 모델코드, 수율 데이터 제공 |
| **동기** | ★☆☆☆☆ — "ESG는 내 KPI가 아니다" |
| **저항** | **강함.** "그거 ERP에 다 있는데 왜 내가 또 입력해야 하나" |
| **정당한 항변** | 맞는 말이다. 이미 있는 데이터를 재입력하게 하는 것은 설계 실패다 |

### 도출 요구사항
- **R18** ERP에 존재하는 데이터는 **수동 입력을 요구하지 않는다.** 엑셀 추출본 업로드 → 자동 파싱을 기본으로 한다. (API 연계는 2차)
- **R19** 업로드 시 **모델코드 ↔ 고객사 품번 매칭을 시스템이 수행**한다. 김 과장이 매칭하게 하지 않는다.
- **R20** 김 과장의 월 소요시간 목표 = **5분 이내(파일 업로드 1회)**.

## P3. 이 반장 — 본사 시설·설비 담당

| 항목 | 내용 |
|---|---|
| **역할** | 전력·용수·가스 검침, 설비 가동시간 |
| **동기** | ★☆☆☆☆ |
| **저항** | 중간. 저항이라기보다 **접근성 문제** — 하루 대부분 현장에 있고 PC 앞에 앉는 시간이 적다 |
| **디지털 숙련도** | 낮음. 엑셀 수식 사용 안 함. 스마트폰은 능숙 |

### 도출 요구사항
- **R21** **모바일 입력이 1순위**다. PC 화면의 축소판이 아니라 **모바일 전용 입력 화면**을 설계한다.
- **R22** 입력 화면에는 **숫자 입력칸 3개 이하 + 사진 첨부 1개**만 둔다. 계량기 사진이 증빙이 된다.
- **R23** **이전 달 값을 기본 표시**한다. 자릿수 오류(1,240 → 12,400)를 즉시 인지하게 한다.
- **R24** 전월 대비 ±30% 이상 변동 시 **입력 시점에 경고**한다. 검증을 박 주임까지 미루지 않는다.

## P4. 왕 주임 — 심양법인 총무 (중국)

| 항목 | 내용 |
|---|---|
| **역할** | 심양법인 전력·연료·용수·폐기물·인사 데이터 |
| **언어** | 중국어. 영어·한국어 제한적 |
| **동기** | ★★☆☆☆ — 본사 지시이므로 따른다. 내재적 동기는 없다 |
| **저항** | **가장 위험한 형태** — 겉으로는 저항하지 않는다 |

### 이 페르소나의 핵심 리스크

중국 현지 업무문화에서 **"본사가 요구한 칸을 비워서 올리는 것"은 무능으로 읽힌다.**
따라서 왕 주임은 데이터가 없을 때 **저항하지 않고 추정치를 채워 넣을 가능성이 높다.**
빈칸보다 훨씬 나쁘다. 빈칸은 발견되지만, 그럴듯한 추정치는 발견되지 않는다.

또한 EP1의 "만kWh 사건"의 당사자다. 왕 주임이 틀린 것이 아니라,
**중국 고지서 관행(万kWh)과 한국 본사의 기대(kWh)가 다른 것**을 시스템이 흡수하지 않았을 뿐이다.

### 도출 요구사항
- **R25** **"미확보 / 확인 중"을 정당한 선택지로 제공**한다. 그리고 **미확보가 감점이 아님을 명시적으로 안내**한다. 빈칸이 죄가 되지 않게 설계한다.
- **R26** 입력 단위는 **법인별로 현지 관행에 맞춰 고정**한다. 심양은 `万kWh`로 입력받고 시스템이 환산한다. 왕 주임이 단위를 변환하지 않는다.
- **R27** **중국어 UI 필수.** 항목명·안내문·오류메시지 전부. 번역은 현지 담당자 검수를 받는다.
- **R28** 증빙 파일 첨부를 **필수**로 한다. 추정치 기입을 구조적으로 억제하는 유일한 방법이다.
- **R29** 통화가 포함된 항목(요금 등)은 **현지 통화로 입력**받고 환율은 시스템이 적용한다. 적용 환율과 기준일을 기록한다.

## P5. Ms. Trang — 빈푹법인 HR&GA (베트남)

| 항목 | 내용 |
|---|---|
| **역할** | 빈푹법인 에너지·환경·안전보건·인사 데이터 |
| **언어** | 베트남어, 영어 가능 |
| **동기** | ★★★★☆ — **현지 법정 보고(Decree 06/2022) 대응이 본인 업무**다. 실제로 가장 협조적일 가능성이 높다 |
| **저항** | 낮음. 단 **업무량**이 실질 제약 |
| **구조적 리스크** | 베트남 제조법인 사무직 이직률이 높다. EP1에서 이미 1회 발생 |

### 이 페르소나의 전략적 가치

Ms. Trang은 **저항할 대상이 아니라 활용할 자원**이다.
빈푹은 3법인 중 유일하게 **법정 의무 가능성**이 있고, 담당자의 동기가 업무와 일치한다.
→ **1차 파일럿을 본사가 아니라 빈푹에서 시작하는 것도 검토 가치가 있다.** (EP8에서 판단)

### 도출 요구사항
- **R30** **베트남어 UI** + 영어 병기 옵션.
- **R31** **담당자 교체 시 권한·이력 이관 절차**를 시스템 기능으로 갖춘다. 계정 삭제가 아니라 승계다. 과거 입력 이력은 후임자가 전부 조회할 수 있다.
- **R32** 빈푹 화면에는 **현지 법정 보고 양식 기준 항목**을 명시한다. Ms. Trang의 업무와 직결되면 입력률이 유지된다.
- **R33** **연간 에너지소비 TOE 환산값을 상시 표시**한다 (R10과 연결). 1,000 TOE 임계치 접근을 담당자가 직접 본다.

## P6. 최 부장 — 본사 구매

| 항목 | 내용 |
|---|---|
| **역할** | 자재 구매 데이터, 협력사 정보, Scope 3 카테고리 1(구매 자재) 원천 |
| **동기** | ★★★★☆ — **고객사 요구 미대응 = 수주 문제**임을 안다 |
| **저항** | 낮음. 단 **협력사에 데이터를 요구하는 것 자체가 부담**이라고 인식 |

### 도출 요구사항
- **R34** 1차 범위에서는 **구매 금액·중량 데이터 업로드**까지만 한다. 협력사 직접 입력은 **2차 과제**로 분리한다.
- **R35** Scope 3는 **1차에서 산정하지 않는다.** 원천 데이터만 축적한다. (Scope 3 산정은 방법론 확정 없이 시작하면 재작업이 확정적이다)
- **R36** 향후 협력사 외부 입력을 붙일 수 있도록 **외부 사용자 권한 체계를 처음부터 고려**해 설계한다.

## P7. 대표이사

| 항목 | 내용 |
|---|---|
| **역할** | 조회. 의사결정 |
| **원하는 것** | **1페이지.** "우리가 준비됐는지 아닌지" |
| **관심사** | 고객사 감사 대응 가능 여부, 수주 리스크, 투입 비용 |
| **관심 없는 것** | 배출계수, 산정 방법론, 입력률 |

### 도출 요구사항
- **R37** 경영진 화면은 **단일 페이지 + 신호등**이다. 3법인 × 준비도. 그래프를 늘리지 않는다.
- **R38** "**지금 고객사 요청이 오면 며칠 안에 답할 수 있는가**"를 지표로 표시한다. 이것이 대표이사 언어다.

## P8. 노사협의회 — 이해관계자 (입력자 아님)

| 항목 | 내용 |
|---|---|
| **역할** | 사회(S) 지표 관련 이해관계자 |
| **관심사** | 산업재해율, 이직률, 교육시간, 근로시간, 임금 관련 지표의 **공개 범위** |
| **우려** | 내부 지표가 대외 공시·고객사 제출로 그대로 나가는 것. 특히 **재해·이직 데이터** |

### 이 페르소나를 빠뜨리면 생기는 일

사회 지표를 시스템에 넣는 순간 **"이 데이터가 어디까지 나가는가"** 라는 질문이 온다.
사전에 정리하지 않으면 협의회 단계에서 프로젝트가 정지된다.

### 도출 요구사항
- **R39** 모든 지표에 **공개등급(내부전용 / 고객사제출 / 대외공시)** 을 속성으로 부여한다.
- **R40** 대외 산출물 생성 시 **공개등급 필터가 자동 적용**된다. 사람의 판단에 맡기지 않는다.
- **R41** 사회(S) 지표 도입 전 **노사협의회 사전 설명 절차**를 로드맵에 포함한다. (EP8)

## 이 에피소드에서 도출된 설계 원칙

스토리를 관통하는 원칙 다섯 개다. EP4·EP5의 모든 설계는 이 원칙에 종속된다.

| # | 원칙 | 의미 |
|---|---|---|
| **P-1** | **입력자는 숫자만 안다** | 환산·배분·배출계수·환율은 전부 시스템이 한다. 입력자에게 판단을 요구하지 않는다. |
| **P-2** | **"모름"이 허용돼야 데이터가 정직해진다** | 빈칸을 강제로 메우게 하는 설계는 추정치를 생산한다. 미확보를 정당한 상태로 만든다. |
| **P-3** | **동기 없는 사람에게는 3분 이하** | ESG는 누구의 KPI도 아니다. 입력 시간이 3분을 넘으면 입력률이 무너진다. |
| **P-4** | **독려는 시스템이, 사람이 하지 않는다** | 박 주임이 30명에게 전화하게 되는 순간 EP1로 되돌아간다. |
| **P-5** | **현지 관행을 본사 기준으로 교정하지 않는다** | 万kWh, 현지 통화, 현지 회계기간을 그대로 받고 시스템이 흡수한다. |

## 미확인 사항 (파트장 검토 필요)

- [ ] 입력 주체 30명+의 실제 구성 — 위 7개 유형으로 커버되는가
- [ ] 공장 설비별 검침 담당이 이 반장 1인인가, 라인별로 분산되어 있는가
- [ ] 심양·빈푹에 ESG 전담자가 있는가, 총무/HR 겸임인가
- [ ] 안전보건 데이터의 현재 관리 주체 (경영지원실 직접인가, 공장 안전관리자인가)
- [ ] 노사협의회에 ESG 데이터 수집 계획을 사전 공유할 시점
