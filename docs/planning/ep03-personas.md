# EP3. 사람들 — "데이터를 만드는 손"

> 목적: 입력 주체를 유형화하고, 각자의 **동기와 저항**에서 권한·UI 요구사항을 도출한다.
>
> **확정 전제 (2026-09-17 개정)**
> - 입력 주체는 **10명 내외**다. (종전 가정 30명+ → 축소)
> - **각 법인별로 업무담당자가 지정되어 있다.** 해외법인은 담당자 1인이 전 항목을 담당한다.
> - 노사협의회 관련 사항은 **본 기획 범위에서 제외**한다. (추후 논의)
>
> 이 에피소드의 전제: **ESG 데이터 입력은 누구의 KPI도 아니다.**
> "잘 협조해줄 것"이라는 가정 위에 설계하면 3개월 안에 빈칸 플랫폼이 된다.

---

## 0. 10명이라는 규모가 바꾸는 것

입력 주체가 30명이 아니라 10명이라는 사실은 설계를 **더 쉽게 만들지 않는다.** 성격을 바꾼다.

| 항목 | 30명 규모였다면 | **10명 규모 (실제)** |
|---|---|---|
| 독려 방식 | 공개 현황판·자동 리마인드 중심 | **개인 알림 중심.** 10명은 서로를 안다. 공개 현황판은 압박이 과하고 관계를 해친다 |
| 승인 부담 | 일괄 승인 필수 | 건별 승인 가능. 대신 **검증 품질 기준을 높일 수 있다** |
| 교육 | 표준 교재·영상 필요 | **1:1 교육 가능.** 대신 교육 내용이 문서화되지 않으면 승계가 끊긴다 |
| **최대 리스크** | 입력률 저하 | 🔴 **단일 실패점.** 해외법인은 담당자 1인이 전부다. 그 1인이 휴가·퇴사·전배되면 **그 법인 데이터가 멈춘다** |

> **10명 규모의 핵심 설계 과제는 입력률이 아니라 승계(繼承)다.**
> EP1의 빈푹 사례(담당자 퇴사로 이력 소실)가 구조적으로 재발 가능한 상태다.

## 2. P1. ESG 데이터 총괄 — 본사 경영지원실

| 항목 | 내용 |
|---|---|
| **역할** | 전 법인 데이터 검증·1차 승인, 배출량 산정, 대외 제출자료 및 보고서 데이터북 작성 |
| **동기** | ★★★★★ — EP1의 3월을 다시 겪고 싶지 않다 |
| **저항** | 없음. 단 **"시스템이 또 하나의 일이 될 것"** 을 두려워한다 |
| **가장 두려운 것** | 입력자들이 안 넣어서 결국 자기가 다 넣게 되는 상황 |
| **현실 제약** | ESG는 업무의 일부다. 인사·노무·총무 업무가 병행된다 |

### 도출 요구사항
- **R15** 대시보드 첫 화면은 "**누가 무엇을 아직 안 넣었는지**"다. 숫자가 아니라 **빈칸 목록**이 먼저다.
- **R16** 마감 독려는 **시스템이 자동 발송**한다. P1이 사람에게 전화하게 만들면 실패한 설계다.
- **R17** *(개정)* 10명 규모이므로 일괄 승인보다 **건별 승인 + 이상치 우선 정렬**이 적합하다. 정상값은 빠르게 통과시키고 이상값에 시간을 쓴다.

## 3. 본사 담당자 — P2 ~ P6

본사 담당자 다섯 명의 공통 특성:

- **동기가 낮다.** ESG는 이들의 KPI가 아니다.
- **담당 항목이 적다.** 2~5개.
- **이미 존재하는 데이터를 요구받는 경우가 많다.** (재입력 요구는 정당한 저항을 부른다)

### P2. 총무·시설

| 항목 | 내용 |
|---|---|
| **담당 데이터** | 전력·용수·가스 사용량, 폐기물 배출·위탁처리, 업무용 차량 연료 |
| **동기** | ★☆☆☆☆ |
| **저항** | 접근성 문제. 현장 이동이 많고 PC 앞에 앉는 시간이 적다 |
| **디지털 숙련도** | 중간. 엑셀 수식은 쓰지 않음. 스마트폰 능숙 |

- **R21** **모바일 입력**을 1순위로 설계한다. PC 화면의 축소판이 아니라 **모바일 전용 입력 화면**.
- **R22** 입력 화면은 **숫자칸 3개 이하 + 사진 첨부 1개**. 계량기·고지서 사진이 증빙이 된다.
- **R23** **이전 달 값을 기본 표시**한다. 자릿수 오류(1,240 → 12,400)를 즉시 인지하게 한다.
- **R24** 전월 대비 ±30% 이상 변동 시 **입력 시점에 경고**한다. 검증을 P1까지 미루지 않는다.

### P3. 인사

| 항목 | 내용 |
|---|---|
| **담당 데이터** | 인원 현황(고용형태·성별·연령), 신규채용·이직, 교육시간, 근로시간, 육아휴직 |
| **동기** | ★★☆☆☆ — 경영지원실 소관이므로 P1과 인접. 협조도는 높다 |
| **저항** | 낮음. 단 **데이터 정의 문제**가 크다 — "이직률"의 분모를 무엇으로 볼 것인가 |

- **R47** 사회(S) 지표는 **산정 정의를 항목에 명문화**한다 (예: 이직률 = 자발적 퇴사자 ÷ 기말 인원). 정의가 흔들리면 다년 추이가 무의미해진다.
- **R48** **급여 시스템·근태 시스템에서 추출 가능한 항목은 업로드로 처리**한다. 수동 재입력을 요구하지 않는다.

### P4. 안전보건

| 항목 | 내용 |
|---|---|
| **담당 데이터** | 산업재해 건수·강도율·도수율, 안전교육 시간, 보건검진, 위험성평가, 아차사고 |
| **동기** | ★★★☆☆ — 안전보건 법정 기록 의무와 항목이 겹친다. 이미 관리하고 있다 |
| **저항** | 낮음. 단 **데이터 민감도가 높다** — 재해 건수는 대외 공개 범위에 대한 판단이 필요하다 |

- **R39** *(개정)* 모든 지표에 **공개등급(내부전용 / 고객사제출 / 대외공시)** 을 속성으로 부여한다.
  근거를 노사협의회가 아닌 **보고서 발간 시 공개범위 판단**으로 재설정한다.
- **R40** 대외 산출물 생성 시 **공개등급 필터가 자동 적용**된다. 사람의 판단에 맡기지 않는다.
- **R49** 안전보건 항목은 **법정 기록서식(산업재해조사표 등)과 항목명을 일치**시킨다. 이중 관리를 없앤다.

> ⏸️ **보류**: 사회(S) 지표의 대외 공개 범위에 대한 협의 절차는 **추후 논의** 사항이다.
> 플랫폼은 R39·R40으로 **어떤 결정이 나와도 대응 가능한 구조**만 갖춘다.

### P5. 생산관리

| 항목 | 내용 |
|---|---|
| **담당 데이터** | 제품별 생산량, 모델코드, 수율, 설비 가동시간 |
| **동기** | ★☆☆☆☆ — "ESG는 내 KPI가 아니다" |
| **저항** | **강함.** "그거 ERP에 다 있는데 왜 내가 또 입력해야 하나" |
| **정당한 항변** | 맞는 말이다. 이미 있는 데이터를 재입력하게 하는 것은 설계 실패다 |

- **R18** ERP에 존재하는 데이터는 **수동 입력을 요구하지 않는다.** 엑셀 추출본 업로드 → 자동 파싱이 기본. (API 연계는 2차)
- **R19** 업로드 시 **모델코드 ↔ 고객사 품번 매칭을 시스템이 수행**한다. P5가 매칭하게 하지 않는다.
- **R20** P5의 월 소요시간 목표 = **5분 이내(파일 업로드 1회)**.

### P6. 구매

| 항목 | 내용 |
|---|---|
| **담당 데이터** | 자재 구매금액·중량, 협력사 정보, 물류 |
| **동기** | ★★★★☆ — **고객사 요구 미대응 = 수주 문제**임을 안다 |
| **저항** | 낮음. 단 **협력사에 데이터를 요구하는 것 자체가 부담**이라고 인식 |

- **R34** 1차 범위는 **구매 금액·중량 데이터 업로드**까지. 협력사 직접 입력은 **2차 과제**로 분리한다.
- **R35** Scope 3는 **1차에서 산정하지 않는다.** 원천 데이터만 축적한다. 방법론 확정 없이 시작하면 재작업이 확정적이다.
- **R36** 향후 협력사 외부 입력을 붙일 수 있도록 **외부 사용자 권한 체계를 처음부터 고려**해 설계한다.

## 4. P7. 심양법인 업무담당자 (중국)

| 항목 | 내용 |
|---|---|
| **담당 데이터** | **심양법인 전 항목** — 에너지·용수·폐기물·생산량·인사·안전보건 |
| **언어** | 중국어. 영어·한국어 제한적 |
| **동기** | ★★☆☆☆ — 본사 지시이므로 따른다. 내재적 동기는 없다 |
| **저항** | **가장 위험한 형태 — 겉으로는 저항하지 않는다** |
| **월 입력 부담** | **30~60분** (본사 담당자의 10배) |

### 이 페르소나의 핵심 리스크 두 가지

**① 침묵하는 추정치**

중국 현지 업무문화에서 **"본사가 요구한 칸을 비워서 올리는 것"은 무능으로 읽힌다.**
따라서 P7은 데이터가 없을 때 저항하지 않고 **추정치를 채워 넣을 가능성이 높다.**
빈칸보다 훨씬 나쁘다. **빈칸은 발견되지만, 그럴듯한 추정치는 발견되지 않는다.**

EP1의 "만kWh 사건"의 당사자다. P7이 틀린 것이 아니라,
**중국 고지서 관행(万kWh)과 한국 본사의 기대(kWh)가 다른 것**을 시스템이 흡수하지 않았을 뿐이다.

**② 단일 실패점**

심양법인 데이터 전체가 1인에게 의존한다. 휴가·병가·전배·퇴사 시 **그 달 데이터가 비고,
복구하려면 본사가 EP1의 3월을 다시 반복**해야 한다.

### 도출 요구사항
- **R25** **"미확보 / 확인 중"을 정당한 선택지로 제공**한다. **미확보가 감점이 아님을 화면에 명시**한다. 빈칸이 죄가 되지 않게 설계한다.
- **R26** 입력 단위는 **법인별로 현지 관행에 맞춰 고정**한다. 심양은 `万kWh`로 입력받고 시스템이 환산한다.
- **R27** **중국어 UI 필수.** 항목명·안내문·오류메시지 전부. 번역은 현지 담당자 검수를 받는다.
- **R28** 증빙 파일 첨부를 **필수**로 한다. 추정치 기입을 구조적으로 억제하는 유일한 방법이다.
- **R29** 통화 포함 항목은 **현지 통화로 입력**받고 환율은 시스템이 적용한다. 적용 환율과 기준일을 기록한다.
- **R50** 해외법인은 **월간 입력 시트 1화면**으로 전 항목을 처리한다. 항목별 개별 화면 이동을 요구하지 않는다.
- **R51** **부담당자(백업) 지정을 필수 항목**으로 한다. 법인별 최소 2인. 1인 의존을 시스템이 허용하지 않는다.
- **R52** **입력 진행률을 담당자 본인 화면에 표시**한다 (예: 24개 항목 중 18개 완료). 30개 항목을 기억에 의존해 챙기게 하지 않는다.

## 5. P8. 빈푹법인 업무담당자 (베트남)

| 항목 | 내용 |
|---|---|
| **담당 데이터** | **빈푹법인 전 항목** |
| **언어** | 베트남어, 영어 가능 |
| **동기** | ★★★★☆ — **현지 법정 보고(Decree 06/2022) 대응이 본인 업무**다. 3법인 중 동기가 가장 높다 |
| **저항** | 낮음. 단 **업무량**이 실질 제약 |
| **구조적 리스크** | 베트남 제조법인 사무직 이직률이 높다. **EP1에서 이미 1회 실현** |

### 이 페르소나의 전략적 가치

P8은 **저항할 대상이 아니라 활용할 자원**이다.
빈푹은 3법인 중 유일하게 **법정 의무 가능성**이 있고, 담당자의 동기가 본인 업무와 일치한다.

→ **1차 파일럿을 본사가 아니라 빈푹에서 시작하는 안**을 EP8에서 검토한다.
   동기가 있는 담당자에게서 먼저 검증하면, 화면 설계 문제와 동기 문제를 분리해 진단할 수 있다.

### 도출 요구사항
- **R30** **베트남어 UI** + 영어 병기 옵션.
- **R31** **담당자 교체 시 권한·이력 이관 절차**를 시스템 기능으로 갖춘다. 계정 삭제가 아니라 **승계**다. 과거 입력 이력은 후임자가 전부 조회할 수 있다.
- **R32** 빈푹 화면에는 **현지 법정 보고 양식 기준 항목을 명시**한다. 본인 업무와 직결되면 입력률이 유지된다.
- **R33** **연간 에너지소비 TOE 환산값을 상시 표시**한다 (R10 연계). 1,000 TOE 임계치 접근을 담당자가 직접 본다.
- **R53** 담당자 교체가 예상되는 법인에는 **입력 방법 안내를 화면 내에 내장**한다. 별도 교재·구두 인수인계에 의존하지 않는다. (항목별 "이 숫자는 어디서 찾나" 안내)

## 6. P9. 경영지원실 파트장 — 최종승인자

| 항목 | 내용 |
|---|---|
| **역할** | 최종 승인, 대외 제출 판단, 공개범위 결정, 프로젝트 오너 |
| **동기** | ★★★★★ — 프로젝트 주관자 |
| **관심사** | 3법인 진행 상태, 이상치, 대외 제출 리스크 |

- **R54** **최종 승인 단계를 P1의 1차 승인과 분리**한다. 대외 제출물은 파트장 승인 없이 생성되지 않는다.
- **R55** 승인 시점에 **"이 수치가 어떻게 만들어졌는지"를 1클릭으로 역추적**할 수 있다 (증빙 → 입력값 → 계수 → 결과).

## 7. P10. 대표이사 — 조회

| 항목 | 내용 |
|---|---|
| **원하는 것** | **1페이지.** "우리가 준비됐는지 아닌지" |
| **관심사** | 고객사 대응 가능 여부, 2027년 보고서 발간 준비도, 투입 비용 |
| **관심 없는 것** | 배출계수, 산정 방법론, 입력률 상세 |

- **R37** 경영진 화면은 **단일 페이지 + 신호등**이다. 3법인 × 준비도. 그래프를 늘리지 않는다.
- **R38** "**지금 고객사 요청이 오면 며칠 안에 답할 수 있는가**"를 지표로 표시한다. 이것이 대표이사 언어다.
- **R56** **2027년 보고서 발간 준비도**를 지표로 표시한다 (필수 지표 확보율 × 연도). 선제 대응의 성과가 보이는 유일한 화면이다.

## 8. 설계 원칙 (개정판)

스토리를 관통하는 원칙 일곱 개다. EP4·EP5의 모든 설계는 이 원칙에 종속된다.

| # | 원칙 | 의미 |
|---|---|---|
| **P-1** | **입력자는 숫자만 안다** | 환산·배분·배출계수·환율은 전부 시스템이 한다. 입력자에게 판단을 요구하지 않는다 |
| **P-2** | **"모름"이 허용돼야 데이터가 정직해진다** | 빈칸을 강제로 메우게 하는 설계는 추정치를 생산한다. 미확보를 정당한 상태로 만든다 |
| **P-3** | **동기 없는 사람에게는 3분 이하** | ESG는 누구의 KPI도 아니다. 본사 담당자 기준 월 3~5분을 넘으면 입력률이 무너진다 |
| **P-4** | **독려는 시스템이, 사람이 하지 않는다** | P1이 9명에게 전화하게 되는 순간 EP1로 되돌아간다 |
| **P-5** | **현지 관행을 본사 기준으로 교정하지 않는다** | 万kWh, 현지 통화, 현지 회계기간을 그대로 받고 시스템이 흡수한다 |
| **P-6** | **본사는 "내 항목만", 해외법인은 "한 화면에 전부"** | 입력 구조를 법인 성격에 맞춘다. 동일 화면을 쓰면 해외법인이 먼저 이탈한다 |
| **P-7** | **1인 의존을 허용하지 않는다** | 모든 입력 항목에 부담당자가 있다. 10명 규모의 최대 리스크는 입력률이 아니라 승계다 |
