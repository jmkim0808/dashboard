# EP5. 장면의 뒷면 — 지표 체계와 데이터 모델

> 목적: EP4의 장면이 **실제로 작동하려면 데이터가 어떤 모양이어야 하는가**를 확정한다.
> 이 문서는 개발 착수의 직접 입력물이다.
>
> **확정 전제 (2026-09-17)**
>
> | 항목 | 결정 |
> |---|---|
> | 보고 프레임워크 | **GRI Standards 주축 + KSSB·IFRS S1·S2 병기** |
> | 1차 지표 범위 | **E 전체 + S 핵심** (G는 2차, 정성 서술 중심이므로 폼 입력 부적합) |
> | 소급 범위 | **2025 ~ 2026 (2개년)** + 증빙 확보 항목만 2024년 선택적 추가 |
> | 제3자 검증 | **첫 회 미검증. 단 데이터 구조는 검증 대응 가능 수준으로 설계** |

## 2. 데이터 모델

### 2-1. 설계 원칙 — 네 가지 불변 규칙

| # | 규칙 | 이유 |
|---|---|---|
| **D-1** | **원본값은 절대 덮어쓰지 않는다.** 입력값은 원본 숫자 + 원본 단위로 저장하고, 환산·산정 결과는 별도 테이블에 둔다 | 계수가 바뀌어도 원본은 불변. 재계산이 항상 가능 |
| **D-2** | **"미입력"과 "미확보"는 다른 상태다.** NULL로 뭉치지 않는다 | 설계원칙 P-2의 데이터 모델 구현. "아직 안 넣음"과 "확인했으나 없음"은 완전히 다른 정보 |
| **D-3** | **산정 결과는 적용 계수 버전을 스냅샷으로 보유한다** | 이미 고객사에 제출한 수치는 계수가 개정돼도 그대로 재현되어야 한다 (R59) |
| **D-4** | **물리적 삭제는 없다.** 모든 변경은 이력으로 남는다 | 제3자 검증 대응 가능 수준 (R45). 첫 회 미검증이라도 구조는 갖춘다 |

### 2-2. 테이블 구조

```
[마스터]
 entity ──┬── site
          ├── user ──── role
          └── metric_assignment ──── metric ──── framework_map
                                        │
 factor (배출계수) ────────────────────┤
 fx_rate (환율) ───────────────────────┤
 data_availability (확보가능 최초연도) ─┘

[트랜잭션]
 entry (입력값) ──┬── evidence (증빙)
                  └── audit_log (변경이력)
 production (생산량) ──── product ──── customer_part_map
 calc_result (산정결과) ──── factor_version_snapshot

```

## 3. 산정 로직

### 3-1. 산식

```
Scope 1  = Σ (연료 사용량 × 연료별 배출계수 × GWP)
           → E02(도시가스), E03(경유), E04(LPG), E05(차량연료)

Scope 2  = E01(전력 사용량) × 지역 전력 배출계수 (location-based)
         + E06(스팀·온수) × 스팀 배출계수

에너지(TJ) = Σ (사용량 × 연료별 순발열량계수)
에너지(TOE) = 에너지(TJ) × 1000 / 41.868      ※ 1 TOE = 41.868 GJ
```

> **TOE 환산이 별도 지표인 이유**: 베트남 Decree 06/2022의 판정 기준이 **1,000 TOE**다.
> 빈푹 법인의 연간 TOE를 상시 표시해야 규제 편입 시점을 놓치지 않는다. (R10, R33)

### 3-2. 법인별 계수 적용 원칙

| 법인 | 전력 계수 | 연료 계수 | 산정 표준 |
|---|---|---|---|
| 본사 (KR) | 한국 전력 간접배출계수 | 국가 고유 배출계수 | 온실가스 산정·보고 지침 |
| 심양 (CN) | **동북전망(东北电网) 지역 계수** | GB/T 32150-2025 기준 | **GB/T 32150-2025** (2026-07-01 시행) |
| 빈푹 (VN) | 베트남 전력망 계수 (MONRE) | Decree 06/2022 부속 방법론 | **Decree 06/2022/ND-CP** |

> EP1의 "어느 연도 동북전망 계수를 썼는지 기록이 없다"는 문제가
> `factor` 테이블 + `calc_result.factor_version_snapshot` 으로 해소된다.

### 3-3. 🔴 비율 지표의 법인 합산 — 흔한 오류

> **3법인 이직률의 평균 ≠ 그룹 이직률.**

비율·집약도 지표는 법인별 결과를 평균하면 틀린다. **분자와 분모를 각각 합산한 뒤 재계산해야 한다.**

```
❌ 그룹 이직률 = (본사 이직률 + 심양 이직률 + 빈푹 이직률) / 3
✅ 그룹 이직률 = (본사+심양+빈푹 퇴사자 합) / (본사+심양+빈푹 기말인원 합)
```

- **R64** 비율·집약도 지표는 **분자·분모를 각각 보유**하고, 집계 시 재계산한다. 비율값 자체를 집계하지 않는다.

적용 대상: 이직률, 도수율, 강도율, 1인당 교육시간, 에너지 집약도, 배출 집약도, 여성 관리자 비율

### 3-4. 통화 환산 정책

집약도 지표의 분모(매출액)는 3법인 통화가 다르다.

| 대안 | 방식 | 판단 |
|---|---|---|
| **권고** | **연평균 환율** | 연간 지표 산출에 적합. 기중 변동을 반영 |
| | 기말 환율 | 재무제표 관행이나, 연간 활동량 지표와 시점 불일치 |
| | 월별 환율 후 합산 | 가장 정확하나 관리 부담. 2차 검토 |

- **R65** 환율 정책을 **연평균 환율**로 고정하고, 적용 환율과 산출 근거를 `calc_result.fx_rate_snapshot`에 기록한다. 정책 변경 시 과거 산출물은 기존 환율로 보존한다.

### 3-5. 제품별 배분 (1차 범위)

```
제품 i의 배출량 = 법인 Scope1+2 × (제품 i 생산량 × 가중치) / Σ(전체 생산량 × 가중치)
```

| 항목 | 1차 | 2차 |
|---|---|---|
| 가중치 | **생산 수량** 또는 **생산 중량** (제품군 특성에 따라 선택) | 공정별 전력 실측, 설비 가동시간 기반 |
| 방법론 | 단순 배분 | **LCA 기반 PCF** |
| 산출 단위 | 제품 단위 배출량 (kgCO2eq/EA) | Cradle-to-gate PCF |

- **R66** 배분 방식(가중치 종류)과 그 선택 근거를 **마스터에 기록**한다. 배분 방식 변경 시 이력이 남고, 과거 산출물은 기존 방식으로 보존한다.

> ⚠️ **한계 명시**: 1차의 생산량 기준 단순 배분은 **고객사가 요구하는 정식 PCF가 아니다.**
> 고객사 요구가 LCA 기반 PCF로 구체화되면 별도 과제가 필요하다. 다만 그때도
> **원천 데이터(전력·연료·생산량)는 이 플랫폼에 있으므로 재수집은 불필요하다.**

## 4. 상태 전이 · 승인 워크플로우

### 4-1. 상태 전이도

```
                    ┌──────────────────────────────┐
                    │                              │
  empty ──입력──▶ entered ──1차승인(P1)──▶ approved ──월확정──▶ closed
    │                 ▲  │                              │            │
    │                 │  └──반송(사유)──▶ returned ──────┘            │
    │                 │                      │                       │
    │                 └──────재입력───────────┘                       │
    │                                                                │
    └──"미확보"──▶ unavailable ──증빙확보시──▶ entered                 │
                        │                                            │
                        └──────────1차승인─────────▶ approved         │
                                                                     │
                                            수정요청 ◀────────────────┘
                                               │
                                               ▼
                                     entered (변경이력 기록)
```

### 4-2. 규칙

| # | 규칙 | 근거 |
|---|---|---|
| 1 | `unavailable`도 **승인 대상**이다. "확인했고 없음"이 승인되어야 P1이 그 항목을 다시 쫓지 않는다 | P-2 |
| 2 | 이상치 플래그는 **차단하지 않는다.** 경고만 하고 입력은 진행된다 | **R60** — 차단하면 담당자가 숫자를 조작한다 |
| 3 | `closed` 이후 수정은 **차단하지 않되 변경이력 필수** | R58 — 소급 입력과 오류 정정은 실제로 발생한다 |
| 4 | 대외 제출물은 **P9 최종 승인 없이 생성되지 않는다** | R54 |
| 5 | 반송 시 **사유 필수**. 사유 없는 반송은 담당자의 동기를 깎는다 | P-3, P-4 |

### 4-3. 권한 모델

| Role | 데이터 범위 | 권한 |
|---|---|---|
| `entry_owner` (주담당자) | **소속 법인만** | 자기 배정 항목 입력·수정(확정 전) |
| `entry_backup` (부담당자) | **소속 법인만** | 주담당자와 동일. **필수 지정** (P-7, R51) |
| `esg_manager` (P1) | 전체 | 조회·검증·1차 승인·반송·산정·산출물 작성 |
| `final_approver` (P9) | 전체 | 최종 승인·공개범위 결정·마스터 관리 |
| `executive` (P10) | 전체 | **요약 화면만** 조회 |
| `admin` | 전체 | 마스터·계정·계수 관리 |

- **R62** (재확인) 법인 단위 **데이터 접근 격리**. 심양 담당자는 빈푹 데이터를 조회할 수 없다.
- **R67** 부담당자가 **미지정인 법인·항목은 마스터 저장이 거부**된다. P-7을 시스템이 강제한다.
