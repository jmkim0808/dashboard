# EP6. 무엇으로 만드나 — 아키텍처 · 비용 · 보안 · 유지보수

> 목적: 자체 웹앱(Cloudflare + Claude API)의 구성을 확정하고, **비용·보안·유지보수 난이도**를 정직하게 산정한다.
>
> 전제: 사내 전산팀 없음. 유지보수 주체는 **경영지원실 파트장 + AI 도구**.
> 이 전제가 기술 선택의 최상위 제약이다. "최신 스택"이 아니라 **"1년 후에도 내가 고칠 수 있는 스택"** 을 고른다.

## 1. 🔴 중국 본토 접속 — 아키텍처 확정 전 필수 검증

### 확인된 사실

| 항목 | 상태 |
|---|---|
| **Cloudflare Pages (`*.pages.dev`)** | **중국 본토에서 제공되지 않음.** `pages.dev` 인증서가 중국 본토에 없음 |
| **Cloudflare Workers (`*.workers.dev`)** | 중국에서 접속 불안정·타임아웃 사례 다수 보고 |
| Cloudflare 전반 | GFW의 DNS 오염·SNI RST 방식으로 **도메인별로 차단 여부가 다르고 시점에 따라 변동** |
| Cloudflare China Network | 존재하나 **Enterprise 플랜 + 중국 파트너(JD Cloud) + ICP 등록** 필요 → 본 프로젝트 범위 초과 |

### 이것이 의미하는 바

> **심양 법인 담당자(P7)가 접속하지 못하면 이 프로젝트는 3법인 통합이 아니다.**
> 그리고 3법인 통합이 아니면 EP2의 전제(그룹 합산 데이터)가 무너진다.

### 대안 비교 — 합법적 경로 전수 검토

> ⚠️ **먼저 못박을 것**: 상용 VPN 서비스를 이용한 우회는 **검토 대상에서 제외**한다.
> 중국에서 무허가 국제구간 VPN 사용은 네트워크안전법 저촉 소지가 있으며,
> **회사가 현지 직원에게 이를 지시하는 것은 현지 법인과 담당자를 법적 리스크에 노출시킨다.**
> 공중 인터넷 위의 IPSEC-VPN 구성도 같은 문제 소지가 있다. 아래는 **합법 경로만** 다룬다.

| # | 대안 | 내용 | 비용 | 적법성 | 판단 |
|---|---|---|---|---|---|
| **A** | **기존 본사 접속 경로 재사용** | 심양법인은 **이미 본사 ERP·그룹웨어에 접속하고 있다.** 그 경로(국제전용회선 또는 기업망)를 그대로 쓴다 | **$0** | ✅ 기존 계약 범위 | 🥇 **최우선 확인** |
| **B** | **자체 커스텀 도메인 + Cloudflare** | `esg.powernet.co.kr`. `pages.dev`/`workers.dev` 미노출로 인증서 문제 해소. **GFW 차단은 보장 안 됨** | $0 | ✅ | ✅ 기본안, 검증 필수 |
| **C** | **국제전용회선 신규 도입** (IPLC / IEPL / MPLS) | 공중 인터넷이 아닌 독립 회선. 라이선스 보유 통신사(KT·China Telecom 등) 제공. **다국적기업 표준 방식** | 월 수십~수백만원 (대역폭별) | ✅ **합법적 정석** | ⚠️ A가 없을 때 검토 |
| **D** | **ICP 등록 + 중국 내 호스팅** | **심양법인(WFOE) 명의로 Beian 신청 가능.** 알리클라우드·텐센트클라우드 등 중국 내 서버 필수 | 클라우드 비용 + 등록 공수 | ✅ 정식 경로 | ⚠️ 이중 배포 부담 |
| **E** | **오프라인 입력 모드** (심양 한정) | 항목·단위가 고정된 엑셀 템플릿 → 메일 제출 → 본사에서 업로드·자동 파싱 | $0 | ✅ | ✅ **폴백 확보 필수** |
| ~~F~~ | ~~상용 VPN 서비스~~ | — | — | ❌ **법적 리스크** | ❌ **배제** |

### 대안별 상세

#### 🥇 A. 기존 본사 접속 경로 재사용 — 가장 먼저 확인할 것

> **심양법인은 지금 본사 시스템에 어떻게 접속하고 있나?**

한국 제조업 중국법인은 통상 본사 ERP·그룹웨어 접속을 위해 **이미 국제전용회선 또는 기업 전용망**을 보유하고 있다. 만약 그렇다면:

- 이 플랫폼을 **그 망 안에서 접근 가능한 경로**에 두면 GFW 문제가 애초에 발생하지 않는다
- **추가 비용 $0**, 추가 계약 없음, 법적 리스크 없음
- 확인 방법: 전산 담당 또는 심양 총무에게 **"본사 ERP를 어떤 회선으로 접속하는가"** 1개 질문

> 🔴 **이것이 EP6에서 가장 먼저 확인해야 할 단 하나의 사항이다.**
> A가 존재하면 B~E 전체가 불필요해진다.

#### C. 국제전용회선 (IPLC / IEPL / MPLS)

- IPLC·IEPL·MPLS는 전송 방식의 차이일 뿐 **국제전용회선으로서 역할은 동일**하다
- 공중 인터넷을 경유하지 않으므로 GFW 대상이 아니고, **상용 VPN과 법적 성격이 완전히 다르다**
- 다국적기업이 중국 네트워크 규제를 준수하면서 본사 시스템에 접속하는 **표준 방식**
- 단 이 플랫폼 하나를 위해 신규 도입하는 것은 과투자다. **본사 ERP 접속 개선 등 다른 필요와 묶어서** 판단해야 한다

#### D. ICP 등록 + 중국 내 호스팅

| 항목 | 내용 |
|---|---|
| 신청 주체 | **외국 기업은 직접 불가.** 중국 내 법인(WFOE) 명의로 신청 — **심양법인이 자기 명의로 가능** |
| 호스팅 | 중국 본토 내 서버 필수 (알리클라우드·텐센트클라우드·화웨이클라우드·차이나텔레콤 등 승인 사업자) |
| 도메인 | MIIT 승인 중국 등록기관 등록, **WHOIS 소유자가 법인명과 정확히 일치**해야 함 |
| 소요 기간 | **약 2~6주** |
| 비용 | Beian(기본 등록) 자체는 무료. 클라우드 비용 + 대행 공수 별도 |
| 유지 의무 | **연 단위 재검증.** 법정대표자·주소·도메인·업무범위 변경 시 **30일 내 MIIT 신고** |

> **판단**: 기술적으로 가능하나 **심양 전용 인스턴스를 별도 운영**해야 하므로
> 배포·데이터 동기화가 이중화된다. 유지보수 주체가 1인인 조건에서는 부담이 크다.
> A·B·C가 모두 불가할 때의 선택지로 남긴다.

#### E. 오프라인 입력 모드 — 폴백이지만 EP1로의 회귀는 아니다

> 중요한 구분: **"입력 폼을 못 열면, 입력값을 구조화된 템플릿으로 받는다."**

EP1의 문제는 "엑셀을 썼다"가 아니라 **① 단위가 불명확했고 ② 항목이 매번 달랐고 ③ 이력이 남지 않았다**는 것이었다. 오프라인 입력 모드는 이 셋을 모두 해결한다.

| EP1 (과거) | E 오프라인 입력 모드 |
|---|---|
| 자유 양식 엑셀, 단위 미표기 | **항목·단위가 고정된 템플릿** (심양은 `万kWh`로 인쇄) |
| 요청할 때마다 항목이 다름 | 시스템이 **매월 동일 템플릿 자동 생성·발송** |
| 개인 폴더에 파일 잔존 | 업로드 즉시 **시스템에 적재, 증빙·이력 동일 보존** |
| 숫자 검증 없음 | 파싱 시 **전월 대비 이상치 자동 검출** |
| 미확보를 추정치로 채움 | 템플릿에 **"미확보" 선택 칸 제공** (P-2) |

→ 담당자 체감은 EP1과 유사하나, **데이터 품질은 온라인 입력과 동등**하다.
→ 부수 효과: 이 모드를 만들어두면 **네트워크 장애·계정 문제 시 전 법인 공통 폴백**으로 쓸 수 있다.

- **R75** *(개정)* **오프라인 입력 모드**를 구현한다 — 항목·단위 고정 템플릿 자동 생성 → 제출 → 업로드·자동 파싱. 중국 접속 실패 시의 폴백이자, 전 법인 공통 장애 대응 경로다.

### 🔴 검증 순서 (EP8 첫 2주)

```
1. [1개 질문] 심양법인은 본사 ERP를 어떤 회선으로 접속하는가?
       │
       ├─ 전용선·기업망 있음 ──▶ 대안 A 확정. 끝. (비용 $0)
       │
       └─ 공중 인터넷 ──▶ 2단계로
                            │
2. 자체 서브도메인에 테스트 페이지 배포 (1시간)
   심양 담당자에게 ① 유선망 ② 모바일 데이터 접속 테스트
   최소 3일 × 1일 2회, 로딩시간·성공률 기록
       │
       ├─ 안정적 ──▶ 대안 B 확정
       │
       ├─ 불안정 ──▶ 대안 E(오프라인 모드) 확정
       │              + C(전용선)는 별도 인프라 안건으로 상정
       │
       └─ 완전 차단 ──▶ 대안 E 확정 + D(ICP) 장기 검토
```

> 어느 경로로 끝나든 **프로젝트는 진행된다.** E가 있기 때문이다.
> 즉 **중국 접속은 프로젝트를 멈추는 리스크가 아니라, 심양의 입력 방식을 결정하는 분기**다.

### 2-2. 계층별 선택과 이유

| 계층 | 선택 | 이유 |
|---|---|---|
| **인증** | **Cloudflare Access (Zero Trust)** | 50명 무료. **자체 로그인·비밀번호·세션 관리를 구현하지 않는다** → 가장 흔한 보안 사고 유형을 구조적으로 제거. 이메일 OTP면 계정 발급도 단순 |
| **화면** | Cloudflare Pages | 정적 호스팅 무료, 대역폭 무과금 |
| **API·로직** | Cloudflare Workers | 서버 관리 불필요. 산정 로직을 코드로 고정(R4) |
| **DB** | Cloudflare D1 (SQLite) | Workers Paid에 포함. 데이터량이 극소하므로 충분 (아래 산정 참조) |
| **파일** | Cloudflare R2 | 10GB 무료. 증빙 파일 보관 |
| **AI** | Claude API (Workers에서 호출) | 증빙에서 숫자 추출 (4절) |
| **알림** | 이메일 발송 서비스 | 마감 리마인드 자동화 (R16, P-4) |

### 2-3. 데이터량 산정 — D1으로 충분한가

| 항목 | 산정 |
|---|---|
| 월 입력 행 수 | 약 70행 (본사 20 + 심양 24 + 빈푹 24) |
| 연 입력 행 수 | 약 840행 |
| 소급분 (2025~2026, 24개월) | 약 1,680행 |
| **5년 누적** | **약 6,000행** |
| 산정결과·이력·마스터 포함 | 약 30,000행 |

> D1의 Workers Paid 포함 한도는 **읽기 250억 행/월, 쓰기 5천만 행/월, 저장 5GB**다.
> 우리 규모는 한도의 **0.001% 미만**이다. **D1 용량은 고려 대상이 아니다.**

### 2-4. 🔴 프레임워크 선택 원칙 — 이 프로젝트의 핵심 기술 판단

> **유지보수 주체가 파트장 + AI라면, 빌드 체인이 복잡한 순간 6개월 후 수정 불가 상태가 된다.**

| 구분 | 권고 | 배제 |
|---|---|---|
| 프론트엔드 | **소수 의존성 + 서버 렌더링 중심.** 화면 수가 11개고 사용자가 10명이다. 복잡한 상태관리가 필요한 화면이 없다 | 무거운 SPA 프레임워크 + 빌드 파이프라인. 의존성 업데이트가 연 단위 부채가 된다 |
| 빌드 | **빌드 단계 최소화.** 코드를 고치면 바로 반영되는 구조 | 트랜스파일·번들러 다단 구성 |
| 스타일 | 단일 CSS 파일 또는 유틸리티 CSS 1종 | 디자인 시스템 다중 도입 |
| 라이브러리 | **꼭 필요한 것만** (차트 1종, 날짜 처리 1종 수준) | "있으면 편한" 라이브러리 누적 |

## 4. Claude API 활용 — 증빙 자동 추출

### 4-1. 유스케이스와 우선순위

| 우선순위 | 용도 | 효과 |
|---|---|---|
| **1** | **증빙 이미지 → 숫자·단위 추출 제안** | 담당자는 사진만 찍는다. 입력 시간 단축 + **자릿수·단위 오류 감소** (EP1 만kWh 사건) |
| 2 | 이상치 발생 시 **확인 질문 생성** (현지어) | "전월 대비 +920%입니다. 단위가 万kWh인지 확인해 주세요" |
| 3 | 항목명·안내문 **다국어 번역 초안** | 현지 담당자 검수 전 초안. 최종 확정은 사람이 (R27) |
| 4 | 보고서 집필 시 **지표 데이터북 기반 초안 작성** | 2027년 보고서 제작 단계 |

### 4-2. 🔴 절대 규칙 — 추출값은 "제안"이다

> **Claude가 추출한 숫자를 자동 저장하지 않는다.**

이유는 설계원칙 P-2와 동일하다. 자동 저장은 **출처를 알 수 없는 숫자**를 만든다.
EP1의 "추정치 12칸"과 구조적으로 같은 문제다.

동작 흐름:

```
담당자가 고지서 사진 첨부
        ↓
Claude가 숫자·단위 추출 → 입력칸에 "제안값"으로 회색 표시
        ↓
담당자가 확인 후 확정 (또는 수정)
        ↓
확정값과 함께 "AI 제안값"도 별도 저장
        ↓
제안값 ≠ 확정값인 건은 검증 화면에서 표시
```

- **R72** Claude 추출값은 **제안**이며 자동 확정되지 않는다. **추출값과 확정값을 분리 저장**하고, 불일치 건은 검증 화면에서 확인 가능하다.

> 부수 효과: 제안값과 확정값의 불일치율을 보면 **추출 정확도를 측정**할 수 있다.
> 정확도가 충분히 높아지면 나중에 자동 확정 범위를 넓힐지 판단할 근거가 된다.

### 5-2. 🔴 해법 — 설계원칙 P-8 신설

> ### **P-8. 개인 단위 데이터는 플랫폼에 올리지 않는다. 집계값만 올린다.**

**개인을 식별할 수 없는 통계·집계값은 개인정보가 아니다.** 따라서 국외이전 규제의 대상이 아니다.

| ❌ 올리지 않는다 | ✅ 올린다 |
|---|---|
| 직원 명단, 사번, 이름 | "2027년 4월 심양법인 총 인원 182명" |
| 개인별 근로시간·급여 | "총 근로시간 31,240시간" |
| 재해자 이름·상병명 | "재해 1건, 근로손실일수 12일" |
| 개인별 교육 이수 내역 | "총 교육시간 420시간" |
| 주민번호·여권번호·연락처 | (해당 없음) |

EP5의 S 지표 체계는 **이미 전부 집계값**이다(S01~S14). 따라서 **지표 설계를 바꿀 필요가 없다.**
필요한 것은 **이 원칙을 명문화하고, 증빙 첨부에서 새는 것을 막는 것**이다.

- **R70** 개인을 식별할 수 있는 데이터는 어떤 항목에도 입력되지 않는다. 입력 화면에 이를 명시한다.

### 5-3. 🔴 증빙 첨부의 구멍 — E 지표와 S 지표를 다르게 다룬다

R28은 "증빙 첨부 필수"였다. 그런데 **S 지표의 증빙은 개인정보를 포함한다.**

| 지표군 | 증빙 원천 | 개인정보 포함 | 증빙 정책 |
|---|---|---|---|
| **E (환경)** | 전기·수도·가스 고지서, 폐기물 위탁 전표 | 없음 | **증빙 필수** (R28 유지) |
| **S (사회)** | 급여대장, 근태표, 재해조사표, 교육 이수 명부 | 🔴 **포함** | **원본 증빙 첨부 금지.** 집계표(이름·사번이 제거된 부서·법인 단위 합계)만 허용 |
| 생산 | ERP 추출 자료 | 없음 | 증빙 필수 |

- **R71** S 지표는 **개인정보가 제거된 집계 증빙만 허용**한다. 급여대장·근태표·재해조사표 원본 업로드는 시스템이 거부한다(안내 포함). **R28의 명시적 예외**다.

> 이 한 줄이 없으면, 선의의 담당자가 급여대장 PDF를 첨부하는 순간
> 중국·베트남 개인정보 국외이전 위반이 성립할 수 있다. **화면에서 막아야 한다.**

| **R73** | 마스터성 변경(계수·환율·항목·담당자·단위·공개등급·매핑)은 **전부 관리 화면에서 수행 가능**해야 한다 | 6-2절 |
| **R74** | 의존성 수를 최소화한다. 추가 시 "1년 후 내가 업데이트할 수 있는가"를 판정한다 | 2-4절 |
| **R75** | **오프라인 입력 모드**를 구현한다 — 항목·단위 고정 템플릿 자동 생성 → 제출 → 업로드·자동 파싱. 중국 접속 실패 시 폴백이자 전 법인 공통 장애 대응 경로 | 1절 |
| **R77** | 상용 VPN을 통한 우회는 **채택하지 않는다.** 현지 법인·담당자를 네트워크안전법 리스크에 노출시키는 방식은 대안에서 배제한다 | 1절 |
| **R76** | **월 1회 전체 데이터 엑셀 덤프**를 자동 생성해 별도 저장소에 보관한다 | 5-4절 |
